# 이지메이커 유선보드 통신 조사와 실물 검증 절차

조사일: 2026-10-28. 

> **2026-10-29 변경:** 앱의 Web Serial 직접 연동(`src/serial.ts`)을 제거했다. 4차시는 이지온에서 수집한 뒤 **데이터 다운로드** CSV를 가져오는 방식으로 바뀌었다. 아래 조사 내용 중 통신 어댑터에 관한 부분은 기록으로만 남긴다. 이지온 CSV 형식(`수집시간,센서 1`, BOM, 시각 형식)은 같은 공개 클라이언트의 다운로드 코드에서 확인했고 `src/ezonCsv.ts`가 이를 읽는다.

## 조사 범위와 도구

- 공식 웹사이트 `https://ezon.ai/`, 공식 자료실 `https://ezon.ai/resources`, 공식 사이트가 현재 공개하는 클라이언트 `https://ezon.ai/assets/index-DNge8NfP.js`를 읽었다. 로그인 영역, 비공개 서비스, 계정 데이터에 접근하지 않았다.
- 로컬 PATH에서 `rea`, `REA`, `reverse-engineering-assistant` 실행 파일을 확인했으나 발견되지 않았다. 사용 가능한 연결 도구에도 REA가 없어 REA 실행 분석은 하지 않았다. 공개 HTML 및 배포 JavaScript를 읽는 방법으로 조사했다.
- 공식 홈페이지는 Web Serial 기반 하드웨어 연결을 설명한다. 공식 자료실에는 유선 USB 보드 기초 활용 문서와 CH341SER 드라이버 항목이 있으나, 문서 본문과 실물 보드 식별은 이번 조사에서 검증하지 않았다.

## 확인된 근거와 그 한계

| 항목 | 직접 확인한 공개 클라이언트 근거 | 해석 범위 |
| --- | --- | --- |
| 브라우저 통신 | `navigator.serial.requestPort({})` 호출 뒤 포트 열기 | 공개 웹 클라이언트는 Web Serial 경로를 포함한다. 사용자의 특정 보드가 이 경로와 호환된다는 실물 증명은 아니다. |
| 포트 설정 | `open({baudRate:e,bufferSize:4096})` | 통신 속도 인자를 전달한다. 이 앱에서도 교사가 확인한 속도를 입력한다. |
| 속도 단서 | `serial_baud_rate:115200`, 생성 코드의 `Serial.begin(115200)` | 115200은 공개 클라이언트/생성 코드의 설정이다. 모든 보드·펌웨어의 고정 프로토콜로 단정하지 않는다. |
| 프레임 단서 | 타 디바이스 안내에 숫자, 쉼표 구분, CRLF와 일정한 센서 순서 설명 | 이 수신 형식에 맞춰 이미 송신하는 펌웨어를 위한 어댑터를 제공한다. 보드가 자동 송신한다는 보장은 없다. |
| 수신 경로 | 열린 포트의 readable을 worker로 전달 | 읽기 스트림이 존재한다. worker 전체와 보드 통신 명령을 검증한 것은 아니다. |
| 핀 목록 | 클라이언트에 A0~A4 선택 목록 | 목록 자체로는 센서 포트를 특정할 수 없다. 이후 제공된 장비 사진 39에서 이번 장비 구성의 A0 물리 연결을 별도로 확인했다. |

공식 계측기 가이드는 유선을 USB/Web Serial로 소개하고 연결 시 값을 받는 사용 흐름을 설명한다. 이는 서비스 사용 설명이며 특정 유선보드 펌웨어의 상세 프로토콜 명세를 대체하지 않는다: https://ezon.ai/wireless-mbl-guides/guide_01_%EA%B3%84%EC%B8%A1%EA%B8%B0%EB%AA%A8%EB%93%9C.html

## 확인되지 않은 항목

정확한 보드 모델과 하드웨어 리비전, 설치 펌웨어, 실제 baud·프레임·초기화/데이터 요청 명령, 전송 열의 밝기 채널, 값 증가 방향, 단위, 원시값→빛의 세기 변환식, 선형성, 포화 범위, 실제 수신 주기는 미확인이다. 앱은 이 통신 정보를 임의로 채우지 않는다. **제공된 구성의 A0 물리 연결은 사진으로 확인했지만, A0와 수신 프레임의 열 번호가 같다는 뜻은 아니다.** 자동 업로드나 추정한 핀별 배선은 제공하지 않는다.

## 제공된 장비 사진으로 확인한 물리 구성

`nc1395-hardware-manual`의 `manual-steps.json`, 사진 검토 목록, 원본 사진 24장과 설명용 삽화 12장을 안내에 사용한다. 자료는 `public/assets/hardware/`에 보존하며, 삽화는 부품 회로도나 핀맵이 아니다.

- 사진 39(38은 중복 사진)에서 전용 다선 커넥터 연결선이 보드 A0에 연결된 구성을 확인했다. 센서 쪽 커넥터와 Light V2.0의 중앙 평면 수광부는 사진 41을 참고한다. 수광부가 LED를 향하며 EZMaker 로고가 있는 뒷면을 향하게 하지 않는다.
- 사진 44의 경로는 **고정 밝기 센서 → 전용 연결선 → 보드 A0 → USB 데이터 케이블 → 선택적인 USB 허브 → 노트북**이다. 센서 연결선을 자동차에 이어 그리지 않는다. 허브는 필수 장비가 아니다.
- micro:bit LED·A/B 면은 앞쪽 초음파 센서 방향을 향한다. 사진 46은 뒷면 부품 소개이며 장착 완료 방향은 사진 48을 사용한다. 자동차 전원 스위치는 사진 26의 뒤쪽 배터리 홀더 아래를 확인하며 전면 P0를 전원 스위치로 취급하지 않는다.
- 원형 독립 LED는 자동차 뒤쪽 micro:bit 후면 쪽에 고정해 뒤에 있는 밝기 센서를 향한다. 자동차가 앞으로 움직이면 LED 발광면–센서 수광부 사이 거리가 증가한다. 자동차 지시등은 실험 광원이 아니다.

이 근거는 사진에서 확인되는 장착·연결 관계에 한정한다. USB 통신 성공, 프로그램 탑재, 모터·B 버튼·초음파 정지, 단위·선형성은 실물 동작 시험으로 확인해야 한다. 수동 주행 시작 기록은 센서와 자동차의 자동 동기화를 뜻하지 않는다.

## 구현 계층

`src/serial.ts`는 기능을 분리한다.

1. `supportStatus`: Web Serial 지원과 보안 컨텍스트 확인. HTTPS/localhost 외 환경과 미지원 브라우저는 CSV·수동·연습 경로 안내.
2. `SerialConnection.connect`: 교사의 명시적인 버튼과 확인된 설정으로 포트 선택. 자동 연결/재연결 없음.
3. `TextDecoder`와 `LineBuffer`: 청크 단위 UTF-8 디코딩, CRLF/LF 줄 분리, 조각난 줄과 여러 줄 처리, 미완성 꼬리 보존. 64KiB 넘는 프레임은 오류.
4. `parseNumericFrame`: 전체 숫자 프레임 검증 후 사용자가 지정한 0부터 시작하는 열을 선택. 빈 필드나 `12abc`를 숫자로 받아들이지 않음.
5. 프레임 콜백: 수신 시각·원문·모든 채널·선택 원시값 전달. 별도의 측정 시작/중지와 자동차 시작 표시를 상위 화면에서 관리.
6. `src/domain.ts`: 주변광 보정과 유효성 판단, 추정 거리, 정규화, 등급 환산. 원시값/보정값 분리. 0 이하·포화·누락·제외 사유 보존.

어댑터는 **수신 전용**이다. 초기화, 샘플 요청, 시작/정지 명령은 보내지 않는다. 이미 쉼표 숫자 프레임을 줄바꿈과 함께 송신하는 펌웨어만 대상으로 하며, 송신을 시작하는 명령이 필요한 보드에는 그대로 사용할 수 없다. 밝기 채널은 물리적 포트 이름과 다르다. 사용자 설정의 `protocolConfirmed` 확인은 기기 검증 기록을 대신하지 않는다.

단위 기본값은 센서 원시값이다. 단위가 확인되고 선형성까지 확인된 경우에만 상대 등급 계산을 허용한다. 예제 데이터는 알려진 이상적 모형에 작은 산포를 추가한 **연습 데이터**이며 실측이 아니다.

## 실물 검증 순서

1. 보드의 모델·버전과 펌웨어를 기록하고, 제공 사진의 Light V2.0–A0 구성과 실제 사용하는 장비가 일치하는지 확인한다. 장비가 다르면 실제 포트 사진/설명서를 새로 기록한다.
2. 공식 앱에서 동일 장비가 동작하는지 확인한다. 다른 앱이 점유한 포트를 닫는다.
3. 펌웨어의 속도·프레임·송신 조건을 문서나 송신 코드와 대조한다. 별도 명령이 필요하다면 검증된 명세를 받은 후 어댑터를 확장한다.
4. 확인된 속도를 입력하고 명시적인 연결 버튼으로 장치를 선택한다. 원문 프레임의 채널 개수와 순서를 확인한다.
5. LED를 켜고 끄고 거리를 바꾸어 실제 변화하는 채널, 증가 방향, 값의 범위와 수신 간격을 확인한다.
6. LED를 끄고 주변광을 여러 번 기록한다. 원시값과 보정값을 대조하고 포화 범위를 확인한다.
7. 단위/변환식과 선형성을 공인 명세 또는 교정 자료로 확인한다. 확인 전 등급 환산을 활성화하지 않는다.
8. USB 분리/재연결, 권한 거절, 미지원 브라우저, 깨진 프레임, 누락 구간을 실물로 검증한다. 측정 기록과 자동차 출발은 별도 시점으로 유지한다.
9. 알려진 거리/시간으로 실제 속력을 반복 측정한다. 등속 구간과 출발 가속·정지 구간을 구분해 분석한다. 초음파 장애물 정지 후 데이터도 주행 구간과 분리하며, 초음파의 5cm 조건을 LED–수광부 사이 거리로 사용하지 않는다.

## 테스트 상태

자동 테스트는 합성 프레임과 모의 Web Serial 읽기 스트림을 이용한다. 조각난 CRLF, 여러 프레임, 잘못된 채널, 비수치·누락, 연결 해제와 재연결, 단위·선형성 제한을 검사한다. 이는 하드웨어 시험이 아니며, 실제 센서 연결 성공·정확도·제품 호환성을 검증했다고 주장하지 않는다.
