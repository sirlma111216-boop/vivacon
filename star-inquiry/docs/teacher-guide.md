# 3~5차시 교사용 진행 안내

중학교 3학년, 2015 개정 과학 3의 별과 우주 단원을 기준으로 하며, 2022 개정 과학 2의 해당 단원에도 재사용한다. 각 차시는 45분이다. 개인의 최초 예상과 관찰 후 설명을 분리해서 남기는 POE 흐름을 유지한다.

## 수업 전

1. 노트북/태블릿에서 앱을 열고 모둠 별칭·수업 코드·역할을 정한다. 학생 실명이나 연락처는 필수가 아니다.
2. 교사용 패널은 수업 조작 편의용이며 서버 인증 기능이 아니다. 정답 공개 시점을 정하고, 외부 자료 링크와 로그인 환경을 점검한다.
3. 처음에는 연습 데이터를 사용해 전체 흐름과 저장·내보내기를 확인한다. 연습 결과에는 반드시 ‘연습 데이터’ 표시를 유지한다.
4. 실제 실험을 할 때는 독립 원형 LED, 고정할 Light V2.0 밝기 센서, 이지메이커 보드와 전용 센서 연결선, 마퀸과 micro:bit, 배터리, 줄자, 바닥 표시, USB 데이터 케이블을 준비한다. LED를 자동차 뒤쪽에 고정하고 센서 수광부를 향하도록 같은 높이로 맞춘다. 책상 가장자리와 케이블이 주행 경로에 걸리지 않게 한다.
5. 자료는 현재 브라우저에 저장된다. 다른 기기와 자동 동기화되지 않는다. 차시 말마다 JSON 백업을 내려받아 다음 차시에 복원한다. 같은 브라우저의 학생 교대 사용 전에는 이전 모둠 기록을 백업한다.

## 장비 사용 설명서 활용

상단 **장비 사용 설명서**는 어느 차시에서든 열 수 있다. 3차시 실험 설계에서는 준비물·앞뒤 방향·실험 배치를 연결하고, 4차시 준비·센서 연결·실제 실험에서도 필요한 단계로 돌아간다. 전체 목록과 12단계 상세 화면에서 설명·확인 사항·원본 사진을 보고 체크한다. 완료 체크는 로컬 학습 기록에 저장되며 실물 연결 성공 표시를 대신하지 않는다. 사진 확대는 닫기 버튼 또는 Escape로 닫는다.

| 단계 | 확인할 관계 | 우선 보는 원본 사진 |
| --- | --- | --- |
| 1. 준비물 | 자동차·micro:bit·독립 LED·센서·보드·전용 연결선·USB·노트북, 자동차와 LED의 별도 전원 | 37·47·25 |
| 2. micro:bit 앞뒤 | LED 25개·A/B 면이 앞면, 뒤쪽 리셋은 A 버튼과 다름 | 45·46 |
| 3. micro:bit 장착 | 전원을 끄고 금색 접점을 아래로, LED·A/B 면을 초음파 센서 쪽으로 | 45·48·25 |
| 4. 뒤쪽 LED | 자동차 뒤쪽 micro:bit 후면 쪽에 고정해 뒤의 밝기 센서를 비춤 | 47·31·34 |
| 5. 자동차 전원 | 뒤쪽 배터리 홀더 아래 스위치, 전면 P0와 구분 | **26**·27 |
| 6. A 버튼 출발 | 주행 코드 탑재를 먼저 확인하고 앞면 기준 왼쪽 A 버튼 사용 | 29·27·28 |
| 7. 초음파 정지 | 앞쪽 장애물에 대한 프로그램 조건을 사전 시험 | 30·31 |
| 8. 센서 커넥터 | 흰 커넥터 모양을 맞춘 전용 다선 연결선 | 41 |
| 9. A0 연결 | 제공 사진에서 확인된 보드 A0 물리 포트 | **39**·38·37 |
| 10. USB 연결 | 보드→데이터 케이블→필요시 허브→노트북 | **44** |
| 11. 배치·정렬 | 센서 고정, 평면 수광부와 LED 발광면 마주 보기, 같은 높이 | 40·42·43·44 |
| 12. 주변광·측정 | LED를 끈 배경값과 켠 시작값 기록, 포화·반사·표시등 영향 점검 | 32·33·35·36 |

단계 번호는 자료를 찾아보는 순서다. 4차시 실습은 **준비물 → 보드 장착 → LED 부착 → 코드 탑재 확인 → 전원 → 센서 연결 → USB → 정렬 → 주행 사전 시험 → 주변광 → 실제 측정**으로 진행한다. 프로그램 업로드는 자동차 전원을 켜기 전의 별도 MakeCode 안내를 따르되 USB 연결 등 실제 장비 상태에 맞춘다.

Light V2.0의 **중앙 평면 수광부**가 LED를 향해야 한다. EZMaker 로고가 있는 센서 뒷면을 LED로 향하게 하지 않는다. 거리는 **LED 발광면–센서 수광부** 사이에서 재며 0보다 큰 시작 거리를 쓴다. 손으로 센서를 든 원본은 방향 참고이고 본 측정에서는 센서를 고정한다. 초음파의 약 5cm 조건은 자동차 앞 장애물까지의 거리이며 밝기 측정 거리나 탁자 추락 방지 기능이 아니다. 장애물 정지 후 자료는 주행 분석 구간과 분리한다.

원본 사진 24장과 설명용 삽화 12장을 재생성하지 않고 사용한다. 삽화와 사진의 방향·포트·버튼이 다르면 사진을 우선하며, 설명은 HTML로 구분한다. 전원은 원본 26, USB는 44를 기본 상세 사진으로 확인하고, 46은 뒷면 소개에만 사용하며 장착 방향은 48을 본다. LED 스위치 조작·접착 수단·핀별 배선·USB 단자 규격을 사진만으로 추정하지 않는다.

## 3차시 — 예상과 실험 설계

| 단계 | 시간 | 진행과 발문 |
| --- | ---: | --- |
| 앞선 수업과 연결 | 5분 | 천상열차분야지도의 별 표현을 떠올린다. ‘밝게 보이는 것은 자체의 빛이 많아서일까, 가까워서일까?’ 광원 자체의 양과 거리를 구분한다. |
| 나의 예상 그래프 | 8분 | 이론을 공개하기 전에 그래프 점을 조정하고 이유와 개인/모둠 별칭을 기록해 최초 예상을 보존한다. 정답에 가까운 모양을 유도하지 않는다. |
| 거리와 빛의 세기 | 8분 | 같은 광원이라는 조건에서 1·2·3·10배 거리와 1·1/4·1/9·1/100 밝기를 조작한다. LED 방향성·주변광·반사·센서 한계가 모형과 다른 점이다. |
| 실험 설계 | 15분 | 거리·밝기의 변인, 통제 조건, 0보다 큰 시작 거리, 간격, 반복, 주변광 측정, 실제 속력 측정, 오차 감소 방법을 정한다. |
| 설계 점검 | 9분 | 체크리스트와 요약을 모둠별로 검토한다. ‘예상과 다른 결과도 의미가 있을까? 그때 어떤 조건을 확인할까?’ |

장비 안내는 기존 일반 실험 삽화를 제공된 하드웨어 매뉴얼의 사진·삽화로 교체한다. 설명용 삽화는 장착 관계를 이해하는 보조 자료이며 회로도·핀맵·축척도가 아니다. 실제 방향과 물리 포트는 원본 사진, 거리는 실제 줄자로 확인한다. 소등 사진의 밝기로 조도·거리 수치를 계산하지 않으며 표지의 돌 별지도도 실제 사료가 아니다.

## 4차시 — 관찰과 설명

| 단계 | 시간 | 진행과 발문 |
| --- | ---: | --- |
| 준비·안전 | 5분 | 센서는 왼쪽 고정, LED 자동차는 오른쪽으로 멀어진다. 빛은 센서를 향한다. 실제 경로와 높이를 점검한다. |
| 마퀸 설정 | 8분 | 장비·확장 버전을 기록하고 MakeCode 9장면 안내를 따라 A 전진·B 정지·초음파 조건을 구성한다. 실제 코드 탑재와 정지를 확인한다. 준비·자동 정지 시간 코드는 별도 선택형이다. |
| 센서 연결·보정 | 8분 | 연결→값 변화→LED 끈 주변광→LED 켠 시작값→포화 여부→위치 조절 순서로 확인한다. 지원 브라우저와 장비 프로토콜 확인 전에는 CSV·수동·연습 입력을 쓴다. |
| 속력 확인·실험 | 12분 | 알려진 거리와 시간을 반복 측정한다. 평균뿐 아니라 편차를 본다. 기록을 먼저 시작하고 실제 주행 시작 기준을 별도로 표시한다. |
| 예상과 비교·설명 | 12분 | 최초 예상, 정규화한 관찰값, 이상적 모형을 비교한다. 제외한 구간은 이유를 남기고 원본은 보존한다. 다음 실험의 개선점을 적는다. |

모터 설정 255는 속력 단위가 아니다. 소프트웨어는 이 값을 cm/s로 환산하지 않는다. 시간에서 거리를 추정하려면 실제 속력, 0보다 큰 시작 거리, 주행 기준 시점이 필요하다. 센서에서 멀어지는 직선 운동의 등속 구간에서만 `r(t)=r₀+v(t−t₀)`를 적용한다. 가속·정지·곡선 주행은 분석 구간에서 구별한다.

### MakeCode 9개 장면과 두 코드의 구분

4차시 **자동차 설정**에는 제공된 화면 9장과 해설을 넣는다. ① 새 프로젝트, ② 이름 입력·생성, ③ 확장 메뉴, ④ `maqueen` 검색과 장비에 맞는 확장 선택, ⑤ v4/v5 분류 확인, ⑥ 출발·정지 블록 해설, ⑦ 다운로드 메뉴, ⑧ 파일로 다운로드, ⑨ HEX 저장 후 `MICROBIT` 드라이브로 전송 순서다. HEX 다운로드와 실제 보드 전송 완료는 다르다.

6번 화면의 시작 블록은 하트만 표시하며 연결 성공이나 모터 정지를 뜻하지 않는다. A 이벤트는 초음파 읽기가 **5cm 미만이면 정지, 그 외에는 전체 모터 정회전 255**를 실행한다. 무한반복은 5cm 미만일 때 정지만 보내며 전진시키는 ‘아니면’ 분기가 없어 장애물이 사라져도 자동 재출발하지 않는다. B 이벤트는 모터를 정지하지만 잠금은 아니므로 A로 다시 출발할 수 있다. 화면에는 준비 시간이나 시간 종료 정지가 없다. 실제 실험에는 시작 모터 정지를 추가하고 동작을 확인한다.

**추가 선택 · 준비 시간과 자동 정지 코드**는 위 화면과 다른 Lite/ROB0148 공식 확장 API 예시다. B 눌림을 짧은 반복으로 확인하고 긴 준비 대기를 쓰지 않으며, **초음파 정지 기능은 없다**. 이 변형을 사용할 때는 준비 중 B 정지, 주행 중 B 정지, A 중복 누름, 시간 종료 자동 정지, 재시작을 점검한다. 두 방식 모두 모터 기계적 제동 지연과 실제 등속성을 코드만으로 보장하지 않는다. 실제 구간별 거리/시간으로 속력을 확인한다.

실제 유선보드 검증을 하지 않은 상태를 ‘연동 구조 구현 완료 / 실제 기기 검증 전’으로 구분한다. 단위가 확인되지 않으면 센서 원시값이다. 보정 후 0 이하 값, 포화, 누락 값은 유효 밝기 계산에 넣지 않으며 양수로 바꾸지 않는다. 센서 선형성과 단위가 확인되지 않으면 실측 데이터의 등급 환산을 사용하지 않는다.

### 이지온에서 직접 수집하는 대안

앱 상단 **이지온 수집 안내**, 시작 화면과 4차시의 **이지온으로 직접 수집하기**에서 별도 안내를 연다. 별빛 탐구실의 센서 연결 기능을 사용하지 않아도 [이지온](https://ezon.ai/)의 **유선 체험하기**에서 이지메이커를 연결하고 수집·그래프 확인·파일 저장까지 진행할 수 있다. 안내에는 교사가 제공한 실제 이지온 화면 10장을 사용한다.

1. 이지메이커와 컴퓨터를 USB로 연결하고 밝기 센서의 실제 연결 포트를 확인한다. 다른 앱이나 탭에서 이 보드에 연결 중이면 측정을 마치고 연결을 해제한다.
2. 이지온의 **블록 코딩 → 입력 → 밝기 센서**에서 값을 선택한다. 이지온 화면의 A0는 예시이며, 이번에 제공된 장비 사진 39에서도 A0 물리 연결이 확인됐다. 실제 연결과 일치시키되 다른 장비에 일반화하지 않는다. 0~100과 0~1023은 블록의 출력 범위이며 lux라고 단정하지 않는다.
3. **EZMAKER 반복 실행** 안에 **데이터 전송 → 센서 데이터 추가하기 → 밝기 센서 측정값(0~100)**을 넣고 **0.1초 동안 기다리기**를 이어 붙인다. 이 대기는 약 10Hz를 목표로 하는 설정이며 실제 수집 시각 간격을 확인한다.
4. **업로드**를 누르고 실제 보드의 USB 직렬 포트를 선택한다. 화면의 COM3는 예시다. 업로드 완료 후 **데이터 분석 → 보드 연결**에서 포트를 다시 선택한다.
5. **수집 시작** 후 빛을 가리거나 비춰 센서값이 반응하는지 확인한다. LED를 끈 주변광과 켠 시작값을 기록하고 포화를 점검한 뒤 실험한다. 실험이 끝나면 **수집 중지**를 누른다. 그래프 설정에서 x축은 수집시간, y축은 센서 1을 확인하고 **데이터 다운로드**로 원본을 보관한다. 첨부 화면의 0 또는 들쭉날쭉한 값은 조작 예시이며 거리–밝기 관계를 입증하는 결과가 아니다.

이지온에서 수집한 자료는 별빛 탐구실에 자동 동기화되지 않는다. 별빛 탐구실에서도 분석하려면 내려받은 파일의 형식을 확인하고 `time,raw,distance` 형식의 CSV로 정리한다. `time`은 수집 시작부터 경과한 초, `raw`는 센서값, 선택 열 `distance`는 cm다. 이지온의 시각 문자열을 그대로 초 단위 숫자로 취급하지 않는다. 시간→거리 변환에는 실제로 보정한 속력, 시작 거리, 주행 시작 시점과 등속 구간 확인이 필요하다. 이지온의 다운로드 파일 형식과 별빛 탐구실 직접 호환은 아직 확인하지 않았다.

화면에 제시된 흐름은 2026-10-28 제공 자료 기준이며 외부 서비스의 메뉴가 바뀔 수 있다. 이 안내 추가는 이 앱의 실물 센서 검증 완료를 의미하지 않는다.

## 5차시 — 밝기를 등급으로 읽기

| 단계 | 시간 | 진행과 발문 |
| --- | ---: | --- |
| 결과 다시 보기 | 5분 | 4차시 결과와 설명을 읽고 등급 숫자가 커질수록 어두워짐을 생각한다. |
| 등급 차이·밝기 비 | 12분 | 1등급/6등급 밝기 비와 이유를 먼저 기록한다. 원본 비바샘 가상실험에서 별을 배치하고 전구로 비교한 뒤 돌아와 관찰을 적는다. |
| 상대 등급 변화 | 8분 | 선형성이 확인된 유효 밝기만 기준 대비 환산한다. 원시값만 있으면 이상적 모형으로 학습한다. 1/100 밝기가 +5 변화임을 설명한다. |
| 겉보기·절대 등급 | 12분 | 태양이 밝게 보이는 까닭을 예상한 뒤 같은 10pc 거리 비교를 관찰한다. 관찰 후 원래 예상과 달라진 점을 기록한다. |
| 확인·성찰 | 8분 | 원본 5분 정리 문제의 두 번째 문항 및 앱의 자체 형성평가를 활용한다. 처음 생각·관찰·근거를 갖춘 현재 설명을 세 문장으로 정리한다. |

정확한 한 등급 비는 `100^(1/5)≈2.512`, 중학교 설명에서는 약 2.5배다. `2.5^5=100`이라고 쓰지 않는다. 교사용 환산식은 `Δm=-2.5 log10(B/B기준)`이다. 이 실험은 기준 대비 상대 등급 변화이며 실제 별의 겉보기 등급·절대 등급 측정이 아니다.

절대 등급은 같은 10pc에서의 밝기 등급이다. 10pc는 10광년이 아니다. 소광을 무시하는 모형에서 `m=M`은 10pc, `m<M`은 10pc보다 가까움, `m>M`은 멂을 뜻한다. 생성 삽화의 별 크기나 곡선을 실제 지름·등급·거리·10pc 경계로 읽지 않는다.
